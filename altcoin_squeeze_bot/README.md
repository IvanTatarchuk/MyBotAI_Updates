# Crowd Squeeze: бот для альткоїн-ф'ючерсів на Bybit

Нестандартна стратегія для USDT Perpetual на Bybit. Вона не вгадує напрямок і не працює на індикаторах типу RSI чи MACD. Бот торгує **проти натовпу в момент, коли натовп починають примусово виносити з позицій**.

## Ідея

На альтах натовп регулярно «перегріває» одну сторону:

1. **Ціна відірвалась від BTC.** Бот рахує бету альта до BTC і дивиться лише на *власний* рух монети (BTC-нейтральний залишок). Якщо цей рух за 4 години більший за 2σ, це аномалія, а не загальний ринок.
2. **Open Interest роздувся (+6% за 4 години).** Нові позиції відкриваються масово.
3. **Funding дорогий.** Одна сторона платить іншій, тобто вона переповнена.

Якщо все це збіглося, сетап **«заряджено»**. Але в перегрітий рух бот не заходить, бо ловити вершину — найшвидший спосіб злити депозит. Він чекає **тригер**:

4. Ціна пробиває мінімум (або максимум) трьох останніх свічок, **і водночас падає OI**. Це означає, що позиції натовпу вже закриваються примусово: ліквідації та стопи. Каскад почався, і бот заходить **за ним**.

| Натовп | Тригер | Угода |
|---|---|---|
| Переповнені лонги (funding > 0, OI ↑, ціна ↑ відносно BTC) | пробій вниз + OI ↓ | **SHORT** (long squeeze) |
| Переповнені шорти (funding < 0, OI ↑, ціна ↓ відносно BTC) | пробій вгору + OI ↓ | **LONG** (short squeeze) |

Фільтр режиму: коли сам BTC рухається більш ніж на 3% за 4 години, нові входи пропускаються. У такий момент ринок рухає BTC, а не натовп на конкретному альті.

## Вихід із позиції

- **Стоп** ставиться за локальний екстремум, у межах від 1 до 3 ATR. Він живе **на біржі** (`stopLoss` в ордері), тож якщо бот впаде, збиток не перевищить запланований 1R.
- **TP1 = 1.5R:** закривається 50% позиції, стоп переноситься в беззбиток.
- **Решта позиції** йде за трейлінг-стопом на відстані 2 ATR від найкращої ціни (chandelier). Так бот забирає весь каскад, а не лише його початок.
- **Тайм-стоп:** через 12 годин позиція закривається, навіть якщо не дійшла ні до стопу, ні до цілі.

## Ризик-менеджмент (депозит $100)

| Параметр | Значення |
|---|---|
| Ризик на угоду | 1.5% депозиту ($1.5 при $100) |
| Макс. плече на позицію | 5x |
| Одночасних позицій | 2 |
| Денний ліміт збитку | −5%, після нього до кінця доби (UTC) нових угод немає |
| Kill switch | −30% від піку, після нього бот повністю зупиняється |
| Монети | топ-40 альтів за оборотом, від $5M/добу (BTC, ETH і стейблкоїни виключені) |

Усі параметри зібрані в `config.py`.

## Запуск

Потрібен лише Python 3.10+, сторонніх залежностей немає.

```bash
# 1. Бектест на реальній історії Bybit (публічне API, ключі не потрібні)
python -m altcoin_squeeze_bot.backtest --days 120 --top 25 --cache data/bars.json --trades

# 2. Paper trading: реальні дані, віртуальні угоди, ключі не потрібні
python -m altcoin_squeeze_bot.bot --mode paper

# 3. Testnet (ключі з testnet.bybit.com)
export BYBIT_API_KEY=... BYBIT_API_SECRET=...
python -m altcoin_squeeze_bot.bot --mode testnet

# 4. Реальні гроші, тільки після пунктів 1–3
python -m altcoin_squeeze_bot.bot --mode live --i-understand-the-risk
```

`--synthetic` у бектесті запускає прогін на згенерованих даних без мережі. Він лише перевіряє, що механіка працює, **і нічого не каже про прибутковість**: squeeze-епізоди там закладені штучно.

### API-ключ

- Створи **суб-акаунт** і поклади на нього тільки ті $100, які готовий втратити.
- Дозволи ключа: лише *Contract → Orders / Positions*. **Без Withdraw.**
- Прив'яжи ключ до своєї IP-адреси.
- Акаунт має бути Unified Trading Account у режимі One-Way.

## Чесно про ризики

- Стратегію **не перевірено на реальних даних**: я писав її в середовищі без доступу до API Bybit. Перш ніж ставити гроші, запусти бектест щонайменше на 90–180 днях і подивись на profit factor, просадку та кількість угод.
- Пороги в `config.py` — стартова точка, а не оптимум. Не підганяй їх під історію до ідеальної кривої: це overfitting, і на живому ринку така крива ламається.
- З $100 кожна угода близька до мінімального ордера Bybit (5 USDT), а комісії та прослизання на альтах з'їдають помітну частку прибутку. Бектест це враховує (0.055% taker + 0.05% slippage на кожну сторону), але реальність буває гіршою.
- Гарантованого прибутку не буде. Бот керує ризиком, а не прибутком.

## Структура

```
config.py        параметри стратегії, ризику, юніверсу та комісій
strategy.py      фічі (бета до BTC, z-score, OI, ATR), детектор сетапу, правила виходу
risk.py          розмір позиції, денний ліміт, kill switch
bybit_client.py  мінімальний клієнт Bybit v5 REST (HMAC-підпис)
data.py          завантаження та вирівнювання свічок, OI, funding і BTC
backtest.py      портфельний бектест (вхід по open наступної свічки, комісії, funding)
bot.py           живий бот: paper / testnet / live
synthetic.py     генератор тестових даних
tests/           юніт-тести (pytest)
```
